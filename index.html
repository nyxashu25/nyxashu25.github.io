DataPit

Node.js · React · PostgreSQL · Elasticsearch · Redis · 91 test files

B2B sales intelligence platform: faceted people and company search, credit-gated email reveal with atomic accounting, outreach sequences, team billing and a Chrome extension for LinkedIn, Gmail and CRM pages.

Node.jsReactPostgreSQLElasticsearchRedisBullMQ
details
  • Search and reveal. Faceted people and company search on Elasticsearch, hydrated from PostgreSQL, with contact details masked until a credit is spent.
  • Credit accounting that survives concurrency. An atomic reserve in Redis, a commit to an append-only PostgreSQL ledger, and a refund when nothing is found. A reaper and a reconciliation job watch for drift and alert instead of silently "correcting" money.

  • Pipeline. Secret scanning with gitleaks, dependency audit, lint, Prettier, tests against real PostgreSQL, Redis and Elasticsearch containers, and Trivy image scans.
  • Shape. One Express monolith plus one worker process, deliberately not microservices. Stack: Node.js 20, Express, Prisma, BullMQ, React 18, Vite, Redux Toolkit, Tailwind, Docker Compose, nginx.

ExpiredDomains Authority Sorter

Chrome Manifest V3 · vanilla JavaScript · no dependencies

Chrome extension that collects expired domains, looks up SEMrush Authority Score, ranks them and shortlists available names on Dynadot. It stops at the cart: checkout stays manual.

Chrome MV3JavaScriptAutomation
details
  • Three stages. Collect domains from ExpiredDomains.net (by scanning pages or importing a CSV), look up the SEMrush Authority Score, then check availability on Dynadot and cart the ones that qualify.
  • Resumable. Stopping and restarting continues where it left off instead of repeating lookups.
  • Careful by design. It never purchases. It paces requests with randomized delays and stops itself on a login wall, a captcha or a cart click that is never confirmed.
  • Local only. Results live in chrome.storage.local. There is no backend and no telemetry.

WP Security Hardening

PHP 7.4+ · WordPress 5.8+ · 57 tests · MIT

Security headers, login attempt limiting, username-discovery blocking and version hiding. Every option can be switched off, and the risky ones start off.

PHPWordPressSecurity
details
  • Nine independent options. Options that can break integrations, such as XML-RPC blocking and HSTS, are off until you choose them.
  • A lockout that cannot be bypassed. It runs after WordPress has checked the password, so a correct password is refused too while a visitor is locked out. Visitor IPs are stored only as hashes.
  • Settings cannot inject headers. Header values are validated against fixed lists, so a bad or hostile setting never reaches the response.
  • Logic apart from WordPress. Settings, header building and the lockout state machine are plain PHP classes, so the 57 tests cover them directly. The security rules were also mutation-checked: I broke them on purpose and confirmed the tests failed.
  • Honest scope. The README says it is not a firewall or malware scanner and does not set a Content-Security-Policy.

WP Lead Form

PHP 7.4+ · WordPress 5.8+ · 98 tests · MIT

A contact form without a CAPTCHA: honeypot, signed time token and rate limiting. Leads are saved privately, emailed to you, and exportable as spreadsheet-safe CSV.

PHPWordPressREST API
details
  • Three quiet spam checks. A hidden honeypot (bots are shown a fake success), a signed time token (too fast, forged or expired is refused) and a per-visitor limit that only counts messages that were actually saved, so a typo never locks anyone out.
  • Private by default. Leads are a private post type visible to administrators only, never exposed on the front end or the REST API. IP addresses are not stored.
  • Works with and without JavaScript. With it, the form validates per field over REST and fetches a fresh token so page caches cannot freeze the timer.
  • Hardened output. The notification email sets the visitor as Reply-To only, strips line breaks from every header value, and the CSV export neutralizes spreadsheet formulas.
  • Tested at the edges. 98 tests, including a failing database and a failing mail server, and the security rules were mutation-checked.

redirect-mapper

Python 3.9+ · 59 tests · standard library only

Checks a 301 redirect map for loops, chains and conflicts, then exports Apache, nginx or Netlify rules.

PythonCLI
details
  • Finds what breaks a migration: loops (including pages that lead into one), self-redirects and conflicting duplicates, each reported with its line number.

How I build

The habits behind the projects above. The numbers are counted from the repositories, and every claim links to something you can inspect.

361automated tests across 7 open-source tools
6 of 7tools with zero runtime dependencies
PHP 7.4 to 8.4plugin tests run on four PHP versions in CI
Linux + WindowsPython tools tested on 3.9, 3.12 and 3.13

01 Keep logic apart from the framework

Decisions live in plain classes and functions that know nothing about WordPress or the browser, with a thin layer on top. That is what lets the plugins' rules be tested directly instead of by clicking around.

02 Break it on purpose

For the security rules I deliberately introduce bugs, such as letting a header contain a line break, and check that the tests fail. In one case a mutant survived, which showed a missing test, so I added it.

03 Safe defaults, honest limits

Options that can break integrations start off. Hashes instead of raw IP addresses. Output escaped, spreadsheet formulas neutralized. Each README states what the tool does not do and what was and was not tested.

04 Prove it in CI

Every repository runs its tests on GitHub Actions across language versions. DataPit's pipeline adds secret scanning, dependency audits and container image scans.

05 Use my own tools

This site is audited with seo-audit, and it ships with a sitemap, robots.txt, structured data, a social preview image and a custom 404 page.

06 Write it down

Install steps, usage, option tables, design decisions and known limitations, in every README. If something was not verified, it says so.
